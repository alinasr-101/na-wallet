# Expense App — OCR ในเครื่อง + ตรวจรูปแบบสลิป

ชุดนี้ต่อยอดจากแพ็กเกจเดิมที่มี Supabase สมัครสมาชิก/เข้าสู่ระบบ และ Google Apps Script บันทึกลง Google Sheets

## สิ่งที่ปรับ

- เปลี่ยน OCR.space/Gemini เป็น **Tesseract.js** อ่านภาษาไทยและอังกฤษในเบราว์เซอร์ของผู้ใช้
- รูปสลิปไม่ถูกส่งไป OCR API หรือ Apps Script เพื่อประมวลผล OCR
- โค้ดพยายามดึงยอดเงิน วันที่ ชื่อผู้รับ/ผู้โอน และเลขอ้างอิงจากข้อความ OCR
- ตรวจรูปแบบเบื้องต้น: ข้อความแจ้งว่าสำเร็จ, คำ/ชื่อธนาคาร, ยอดเงินที่ไม่กำกวม, วันที่ที่ถูกต้องและไม่ใช่อนาคต
- ถ้าเบราว์เซอร์รองรับ `BarcodeDetector` จะตรวจว่ามี QR ในภาพหรือไม่ (การพบ QR ไม่ได้แปลว่าสลิปแท้)
- ก่อนบันทึก ผู้ใช้ต้องตรวจยอด/วันที่และติ๊กยืนยันด้วยตนเอง
- Apps Script เก็บเลขอ้างอิงและ SHA-256 fingerprint ของผล OCR/QR เพื่อป้องกันการเพิ่มสลิปเดิมซ้ำในบัญชีเดียวกัน
- คงระบบสมัครสมาชิก/เข้าสู่ระบบ Supabase และการผูกข้อมูลกับ UUID ผู้ใช้ไว้

## ข้อจำกัดสำคัญของการตรวจสลิป

ระบบนี้ตรวจได้เพียง **ความครบถ้วนและความสมเหตุสมผลของข้อมูลที่อ่านจากภาพ** รวมถึงการซ้ำกับสลิปที่เคยบันทึกในบัญชีเดียวกันเท่านั้น ไม่สามารถยืนยันได้ว่าเงินเข้าบัญชีจริง สลิปออกจากแอปธนาคารจริง หรือภาพไม่ถูกแก้ไข เพราะไม่มีการเชื่อมต่อระบบตรวจสอบธุรกรรมของธนาคาร/ผู้ให้บริการ การแสดงผล “ตรวจรูปแบบเบื้องต้นผ่าน” จึงไม่ใช่การรับรองสลิปแท้

หากต้องการยืนยันธุรกรรมจริง ต้องมีช่องทางตรวจสอบจากธนาคารหรือผู้ให้บริการที่รองรับ (เช่น API ตรวจสอบรายการ/QR reference) ซึ่งอยู่นอกขอบเขตของ OCR แบบออฟไลน์และอาจมีค่าใช้จ่าย

## บริการและการเชื่อมต่อที่ยังใช้

- Supabase Auth ยังใช้สำหรับสมัครสมาชิก/เข้าสู่ระบบและตรวจ access token ตามระบบเดิม
- Google Apps Script/Google Sheets ยังใช้เก็บข้อมูล
- Tesseract.js และไฟล์โมเดลภาษาไทย/อังกฤษถูกดาวน์โหลดจาก CDN ในการเริ่มใช้งานครั้งแรก แต่การประมวลผลภาพ OCR เกิดในเบราว์เซอร์ ไม่ได้เรียก OCR API และไม่ได้อัปโหลดภาพไปยัง CDN
- ต้องเปิดเว็บผ่าน HTTPS และเชื่อมต่ออินเทอร์เน็ตในครั้งแรกเพื่อดาวน์โหลดไลบรารี/โมเดล หากต้องการให้ทำงานโดยไม่ติดต่อ CDN เลย ต้องดาวน์โหลดไฟล์ Tesseract worker/core และ traineddata มาโฮสต์ไว้บนเว็บของคุณเอง

## A. ตั้งค่า Supabase (ถ้ายังตั้งจากแพ็กเกจเดิมแล้ว ข้ามได้)

1. สร้าง Supabase project
2. ไป Project Settings → API แล้วคัดลอก Project URL และ Publishable key (หรือ anon key รุ่นเดิม)
3. เปิด Authentication → Providers → Email
4. ตั้งค่า Confirm email ตามต้องการ
5. ใน `index.html` แก้ค่า `SUPABASE_URL` และ `SUPABASE_ANON_KEY` ให้เป็นค่าจริง ห้ามใส่ service_role/secret key ในหน้าเว็บ

## B. ตั้งค่า Google Apps Script

1. เปิด Google Sheet เดิม → Extensions → Apps Script
2. แทนที่โค้ดใน `Code.gs` ด้วยไฟล์ `Code.gs` ใน ZIP
3. ไป Project Settings → Script Properties แล้วตั้ง:
   - `SUPABASE_URL` = Project URL เดียวกับหน้าเว็บ
   - `SUPABASE_ANON_KEY` = Publishable/anon key เดียวกับหน้าเว็บ
4. Save แล้ว Run `setup()` หนึ่งครั้ง และอนุญาตสิทธิ์
5. Deploy → Manage deployments → Edit → New version → Deploy
6. ตั้ง Web app: Execute as = Me, Who has access = Anyone
7. ถ้า URL `/exec` เปลี่ยน ให้แก้ `API_URL` ใน `index.html`

ไม่ต้องตั้ง `OCRSPACE_API_KEY` หรือ `GEMINI_KEY` อีกต่อไป

## C. อัปเดตหน้าเว็บ

1. สำรองไฟล์เว็บเดิมก่อน
2. อัปโหลด `index.html` จาก ZIP ไปแทนไฟล์เดิมบนโฮสต์
3. เก็บไฟล์รูป ไอคอน โฟลเดอร์ `icons/`, `pets/`, `manifest.json`, `sw.js` และไฟล์ประกอบเดิมไว้ ไม่ต้องลบ
4. หากเว็บใช้ Service Worker/PWA ให้เปลี่ยน cache version ใน `sw.js` หรือเคลียร์ cache แล้วโหลดเว็บใหม่ เพื่อไม่ให้เบราว์เซอร์ใช้ `index.html` เก่า
5. เปิดเว็บผ่าน Chrome/Edge รุ่นใหม่ ล็อกอิน แล้วเลือก “อ่านจากสลิปโอนเงิน”

## D. คอลัมน์ใน Google Sheets

เมื่อ Run `setup()` ระบบจะเพิ่มหัวคอลัมน์ `slip_ref` และ `slip_hash` ในคอลัมน์ I–J ของชีต `Expenses` เพื่อเก็บข้อมูลป้องกันรายการซ้ำ แถวเก่าจะยังคงอยู่ และข้อมูลรายการเดิม 8 คอลัมน์ไม่ถูกเปลี่ยน

## E. ย้ายข้อมูลเดิม

หากใช้ migration จากแพ็กเกจเดิม ให้ทำตามขั้นตอนเดิม: ตั้ง `LEGACY_USER_ID` เป็น UUID ของบัญชีเจ้าของข้อมูลเดิม แล้ว Run `migrateLegacyRowsToAccount()` หนึ่งครั้ง จากนั้นลบ Script Property นี้

## ข้อจำกัดและการทดสอบ

- OCR ภาษาไทยอาจอ่านผิดเมื่อภาพเบลอ เอียง มีการปิดบังข้อมูล หรือรูปแบบสลิปต่างกันมาก
- ระบบจะไม่บันทึกจาก OCR โดยอัตโนมัติ ต้องตรวจยอด/วันที่และยืนยันเอง
- ถ้า OCR แยกยอดไม่ได้หรือไม่พบข้อความสำเร็จ/ชื่อธนาคาร ระบบจะแจ้งไม่ผ่านเกณฑ์ และให้กรอกเองได้
- การป้องกันสลิปซ้ำใช้เลขอ้างอิงที่อ่านได้และ fingerprint ของข้อความ OCR/QR จึงอาจพลาดได้หาก OCR อ่านข้อความต่างกันมาก หรือเลขอ้างอิงอ่านผิด
- โค้ดนี้ยังไม่ได้ Deploy หรือทดสอบกับ Supabase และ Google Sheet จริงของคุณ ต้องทดลองด้วยสลิปตัวอย่างก่อนใช้งานจริง
